# 007 开发执行规范（给 Codex 看）

> 目的：后续开发 `novel_producer` / `novel_publisher` 时严格按本文件执行，避免跑偏。

## 一、硬约束（不可偏离）

1. 项目拆分为两个独立 Python 项目：
   - `novel_producer`: 只生产，不发布
   - `novel_publisher`: 只上传+推送，不转换

2. 分类规则来自源目录名：
   - 格式：`<category>-<cn_novel_name>`
   - `<category>` 直接映射目标 `novels/<category>/`

3. 导读必须每章存在：
   - 每章必须有 `chapters/*.md` 和 `annotations/*-guide.md`
   - 任一缺失，章节状态不得标记为可发布

4. `author` 字段不作为必填依赖：
   - 内容规范中不再要求作者语义
   - 前端/内容结构层面按“无作者”逻辑产出

5. `info/index.md` 节流更新：
   - 首章必生成
   - 每 100 章更新一次（默认阈值，可配置）
   - 非阈值章节禁止重复调用大模型更新小说级信息

6. 发布阶段禁止做转换：
   - `novel_publisher` 不得改写内容，不得重命名，不得补写结构
   - 只做：选择目录 -> 上传到内容仓 -> push main

7. 网络代理策略固定：
   - 优先 `127.0.0.1:10809`
   - 失败回退 `127.0.0.1:10808`
   - 推送必须使用 GitHub token


## 二、目录与产物契约（Producer 输出）

```txt
novels/
  <category>/
    <novel_slug>/
      info/index.md
      chapters/<chapter_code>-<slug>.md
      annotations/<chapter_code>-<slug>-guide.md
      meta/novel.json
      meta/<chapter_code>-<slug>.json
```

### 章节编号规范
- `chapter_code` 固定 4 位：`0001, 0002, ...`
- 文件名、frontmatter、状态索引三者必须一致

### 状态机最低字段
- `cleaned_done`
- `story_done`
- `guide_done`
- `meta_done`
- `ready_for_publish`
- `published_done`（发布项目写入）


## 三、提示词装配规则（Producer）

每次调用大模型的上下文必须包含：
- 基础常驻：`1 + 2 + 3 + 6`
- 正文轮额外：`4`
- 导读轮额外：`5`

其中：
- `6-增量术语与临时规则.md` 由脚本+模型共同维护
- 每轮调用都必须读取最新版本的 `6`


## 四、低 token 策略（必须执行）

1. 小说级元数据（`info/index.md` / `meta/novel.json`）：
   - 首章调用
   - 每100章调用
   - 其余章节直接复用本地状态并做计数更新

2. 章节级 meta：
   - 每章生成独立文件
   - 优先复用正文轮/导读轮已返回字段
   - 禁止单独再开高成本模型调用（除非字段缺失）


## 五、Publisher 交互契约（CLI）

运行行为必须如下：

1. 扫描 `novels/` 分类目录，编号展示
2. 输入分类编号
3. 扫描小说目录，编号展示
4. 输入小说编号
5. 二次确认：`1确认上传推送 / 2取消`
6. 实时打印：
   - 正在扫描...
   - 正在上传...
   - 上传文件数量
   - 提交 hash
   - push main 成功/失败
   - 部署触发结果（由 push 成功推断）


## 六、异常处理要求

1. 断点续跑：
   - 任意阶段失败，不得丢进度
   - 重启后从最近未完成章节继续

2. 幂等：
   - 已完成章节不得重复生成
   - 已发布章节不得重复上传（除非强制参数）

3. 网络异常：
   - 上传/推送失败必须明确报错并保留现场状态
   - 给出“可重试”命令提示


## 七、开发顺序（强制）

1. 先实现 `novel_producer` 骨架 + 状态机
2. 再实现双轮模型调用与 1~6 提示词装配
3. 再实现输出契约（novels 标准结构）
4. 最后实现 `novel_publisher`（选择、确认、上传、推送）
5. 最后做端到端联调：内容仓 push -> 前端仓自动部署


## 八、完成定义（DoD）

全部满足才算完成：
- [ ] 新小说首章能完整产出（正文+导读+meta）
- [ ] 连续处理 100 章可稳定运行
- [ ] 中断后续跑不重头
- [ ] 发布项目能按选择上传指定小说目录
- [ ] push main 成功并触发部署

## 九、强提醒（完成两个PY项目后立即执行）

1. 当前系统阶段允许先产出 `meta/*.json` 但前端未完全消费。  
2. 两个 PY 项目完成后，必须立即发起“前端消费 meta 全量接入”任务。  
3. 接入目标：章节关键词、SEO 标题、meta 描述、导读标签、小说级 meta 均应在前端有对应用途。  
4. 禁止长期保留“产出不被使用”的状态。
