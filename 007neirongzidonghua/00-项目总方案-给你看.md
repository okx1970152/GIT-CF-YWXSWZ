# 007 内容自动化项目总方案（给你看）

## 一、项目目标

本目录下将建设两个独立 Python 项目：

1. `novel_producer`（生产项目）  
   负责中文原素材章节的清洗、正文翻译、导读生成、章节级元数据落盘、断点续跑。  
   **不负责上传仓库，不负责触发部署。**

2. `novel_publisher`（发布项目）  
   负责从 `novels` 最终产物目录中选择“分类 + 小说”，将该小说目录上传到内容仓并推送 `main`。  
   **不做转换，不做二次加工。只做上传与推送。**


---

## 二、你确认后的核心业务规则

## 1) 分类由源目录前缀决定

源目录示例：`xuanhuan-长生界`  
其中：
- `xuanhuan` => 网站分类（目标目录 `novels/xuanhuan/`）
- `长生界` => 中文小说名（生成英文 slug 作为小说目录名）

最终目标目录示例：
`novels/xuanhuan/sanctuary-of-immortals/`


## 2) 导读是必须，不是可选

每章都必须有：
- 正文（chapter）
- 导读（annotation/guide）

缺一不可。


## 3) 作者字段不再使用

你确认所有小说为模型创作/改写，不保留作者概念。  
后续内容规范会去掉 `author` 强依赖（或以固定空值策略兼容，最终以前端适配结果为准）。


## 4) `info/index.md` 更新策略（省 token）

- 新小说第 1 章时必须生成
- 后续不每章更新
- 每累计 100 章更新一次（阈值可配置）
- 你手动触发“全量刷新”时可额外更新


## 5) 发布策略（避免频繁部署）

生产项目与发布项目彻底分离：

- `novel_producer` 可以连续跑很多章（例如 100 章）
- 你觉得时机合适，再启动 `novel_publisher`
- `novel_publisher` 一次性上传并推送，触发一次部署


---

## 三、`novel_producer` 目标产物结构

```txt
novels/
  <category>/
    <novel_slug>/
      info/
        index.md
      chapters/
        0001-xxx.md
        0002-xxx.md
      annotations/
        0001-xxx-guide.md
        0002-xxx-guide.md
      meta/
        novel.json
        0001-xxx.json
        0002-xxx.json
```

说明：
- `chapters` 与 `annotations` 每章都必须生成
- `meta` 每章独立文件，便于断点与发布检查
- `novel.json` 和 `info/index.md` 低频更新（首章 + 每100章）


---

## 四、`novel_publisher` 交互流程（你要求的 CMD 体验）

启动后自动执行：

1. 扫描最终产物目录 `novels/`，罗列分类（编号）
2. 你输入分类编号（如 `1`）
3. 扫描该分类下小说目录，罗列小说（编号）
4. 你输入小说编号（如 `2`）
5. 二次确认：
   - `1` 确认上传并推送
   - `2` 取消
6. 确认后执行上传与推送，并实时打印日志：
   - 正在上传...
   - 共上传多少文件
   - 提交是否成功
   - 推送 main 是否成功
   - 部署触发是否成功（依据 push 结果）


---

## 五、网络与推送规则（固定）

发布项目每次运行时优先自动挂代理：
- `127.0.0.1:10809`
- 若失败自动回退 `127.0.0.1:10808`

GitHub 操作统一使用 token（非交互账号登录）。


---

## 六、最终验收标准

满足以下即算成功：

1. 生产项目可按章节持续跑，支持中断续跑，不卡死
2. 每章都生成正文 + 导读 + chapter meta
3. `info/index.md` 按“首章 + 每100章”更新
4. 发布项目可按“分类->小说->确认”上传推送
5. 推送使用 token，且代理逻辑生效
6. 内容仓更新后能触发前端自动部署

---

## 七、后续必须立即处理的前端对接提醒（重要）

在两个 Python 项目完成后，下一阶段必须立刻处理这件事：

- 前端必须消费并使用 `meta` 产物（尤其是每章 `meta/<chapter>.json`），不能只生成不用。
- 目标是“生产出来的内容全部被前端吃掉”，避免信息浪费。

具体要求：
- 章节级关键词、SEO 标题、meta 描述、导读标签，需在前端页面与元数据层完成接入。
- `meta/novel.json` 与 `meta/<chapter>.json` 的关键字段要映射到实际页面或 SEO 输出。
- 该任务是两个 Python 项目上线后的第一优先级待办。
