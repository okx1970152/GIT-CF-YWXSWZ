# 结论：你原来的三阶段方向正确，但需要补 7 个关键缺口

你现在不是单纯“做一个小说站”，而是在把现有 Blogger 模板里的能力迁移成一个 **Next.js 14 + 本地 Markdown 内容仓库 + 可 SEO 抓取 + 可广告变现 + 可持续扩展的小说站系统**。

你上传的 Blogger 模板已经有几个很好的原型：双栏阅读、`.novel-container`、`.story-text`、`.annotation-box`、注释栏折叠、阅读偏好、首页系列目录重写、`.seo-topics` 标签区等；章节 HTML 也已经按正文轨道和注释轨道拆开了。新方案应该保留这些产品逻辑，但不要继续依赖 Blogger 的客户端脚本重写。Next.js 版本要改成 **服务器端生成页面、服务器端解析 Markdown、服务器端输出 SEO 标签**。 

下面是我整理后的完整方案和可直接投喂 Cursor 的分阶段提示词。

---

# 一、先补齐你原提示词里缺的关键点

## 1. 要区分“内容文件路径”和“前端 URL 路由”

你原文写：

```txt
Root: /novels/[CategoryName]/[NovelID]/
```

这适合作为 **内容文件目录**，但不应该直接让用户看到 `[CategoryName]` 这种大写混合路径。建议统一：

```txt
内容目录：/novels/xuanhuan/sanctuary-of-immortals/
前端 URL：/novels/xuanhuan/sanctuary-of-immortals
章节 URL：/novels/xuanhuan/sanctuary-of-immortals/chapters/0001
```

原因：分类路径应该全小写、kebab-case，避免大小写导致部署环境、sitemap、canonical URL 不一致。

---

## 2. `fs + gray-matter + ISR` 不能误解

如果内容 Markdown 被打包进 Next.js 项目，**推送 GitHub 后通常是触发重新部署**，不是 ISR 自动读取 GitHub 新文件。Next.js 14 的 `generateStaticParams` 会在 `next build` 时生成动态路由参数，并且官方文档明确说明 ISR 期间不会再次调用 `generateStaticParams`。所以新增章节文件后，最稳的路径是：GitHub push → 自动部署 → 重新生成路径。([Next.js][1])

ISR 仍然有用，但主要用于：

```txt
已存在路径的内容再验证
远程 fetch 内容的缓存更新
广告配置/搜索索引等可重新验证数据
```

如果你希望后台 `/admin` 在生产环境直接改广告并立即生效，不能只靠 `fs.writeFile`，因为很多部署平台的运行时文件系统不可持久写入。更稳的做法是：

```txt
开发环境：写本地 /data/ads.json
生产环境：通过 GitHub Contents API 提交 ads.json 到内容仓库
提交后：触发 revalidatePath 或等待 GitHub 自动部署
```

Next.js 14 支持按时间 revalidate，也支持在 Server Action 或 Route Handler 内用 `revalidatePath` / `revalidateTag` 做按需再验证。([Next.js][2])

---

## 3. 必须锁定 Next.js 14 类型写法

Cursor 很容易生成 Next.js 15/16 的写法，比如：

```ts
params: Promise<{ id: string }>
```

但你指定的是 Next.js 14。Next.js 14 官方文档里的 `generateMetadata` 参数还是普通对象：

```ts
params: { id: string }
```

所以提示词里要明确写：**Use Next.js 14 App Router conventions, not Next.js 15/16 Promise params style.** ([Next.js][3])

---

## 4. 上一章/下一章不能只做数字减一加一

你原本说：

```txt
current 0080 -> prev 0079, next 0081
```

这是对的，但要补充：

```txt
必须检查对应 Markdown 文件是否真实存在。
不存在时按钮 disabled。
不要跳到 0082，除非用户明确要求“跳到下一个存在章节”。
```

否则中间缺章时会生成死链。

---

## 5. Related Topics 必须服务器端解析并输出为真实 `<a>`

你的 Blogger 模板里已经有 `.seo-topics` 视觉样式基础，章节 HTML 的注释栏也天然适合放这些主题标签。迁移到 Next.js 后，不要用客户端 JS 动态生成标签。应该在服务器端解析 `guide.md` 底部：

```md
Related Topics: #DaoHeart #OuterCourt #SectTrial
```

然后输出：

```html
<a href="/search?q=DaoHeart">#DaoHeart</a>
```

这样搜索引擎能直接抓到，而不是等 JS 执行。你原文件里的 `.seo-topics` 和注释栏结构可以作为视觉参考。

---

## 6. 广告后台要补“持久化策略”

你写了 `/admin` 和 9 个广告位，但没有说明广告配置存哪里。建议：

```txt
/data/ads.json
```

结构固定为：

```json
{
  "directory": {
    "top": {},
    "mid": {},
    "bottom": {}
  },
  "reading": {
    "top": {},
    "mid": {},
    "bottom": {}
  },
  "guide": {
    "top": {},
    "mid": {},
    "bottom": {}
  }
}
```

每个广告位支持：

```ts
type AdSlot = {
  enabled: boolean;
  type: "empty" | "text" | "image" | "html";
  text?: string;
  link?: string;
  imageUrl?: string;
  html?: string;
};
```

渲染规则：

```txt
empty / disabled：返回 null，不能有 margin、padding、placeholder。
image + link：图片包链接。
text + link：30px centered text link。
html：只在后台可信内容下 dangerouslySetInnerHTML。
```

---

## 7. 需要加验收标准，否则 Cursor 容易“写完但没做对”

每个阶段都要让 Cursor 输出：

```txt
Files created/modified
How to test
Acceptance criteria
Known limitations
```

这会显著减少“代码看起来很多，但页面跑不起来”的风险。

# 六、最重要的避坑清单

| 风险                           | 正确做法                                  |
| ---------------------------- | ------------------------------------- |
| Cursor 生成 Next.js 15/16 参数写法 | 明确要求 Next.js 14，不用 Promise params     |
| 新章节 push 后页面不出现              | GitHub push 触发重新部署；不要误以为 ISR 会重新扫描新文件 |

| 后台生产环境写本地文件                  | 用 GitHub Contents API 或明确提示不能保存       |
| 首页卡片变成普通 grid                | 必须做 `1 fixed + horizontal scroll`     |
| 阅读页行宽过大                      | 主内容限制 820–920px                       |
| Hero 出现在阅读页                  | Hero 只放在 Home/Category/Directory 页面   |
| 分类大小写混乱                      | 文件夹用小写 slug，展示名用英文 Title Case         |
